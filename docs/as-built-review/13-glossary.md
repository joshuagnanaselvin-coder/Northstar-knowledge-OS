# Glossary

**NorthStar Knowledge OS — Terminology Reference**

---

## A

**AI (Artificial Intelligence)**
In the context of this platform, refers to the planned LLM integration for generating answers in Spiral Search. Currently implemented as hardcoded mock responses.

**API (Application Programming Interface)**
The set of 12 REST endpoints exposed by the FastAPI backend under the `/api` prefix.

**Approval Workflow**
A structured process for reviewing and approving knowledge assets before publication. Stages: Draft → Submitted → Champion Review → Leader Approval → Published.

**Asset**
Short for "Knowledge Asset" — any piece of knowledge content in the system (procedures, manuals, case studies, etc.).

**Audit Log**
A record of who accessed or modified what data and when. Not yet implemented (Phase 3).

**Authentication**
The process of verifying a user's identity. Currently name-based only; password + JWT authentication planned for Phase 2.

**Authorization**
The process of determining what an authenticated user is allowed to do. Currently UI-only; server-side enforcement planned for Phase 2.

**Auto-assignment**
The logic that automatically assigns owner, reviewer, and approver when a new knowledge asset is created.

---

## B

**Backend**
The FastAPI Python application that serves the REST API and manages data.

**bcrypt**
A password-hashing algorithm planned for implementation in Phase 2. Currently not used.

---

## C

**Case Study**
A type of knowledge asset that documents a real-world scenario and its outcome.

**Champion**
A user role with review-level permissions. Champions review submitted knowledge assets during the Champion Review stage.

**Champion Review**
The second stage of the approval workflow, where a Champion reviews a submitted asset for technical accuracy.

**CI/CD (Continuous Integration / Continuous Deployment)**
Automated pipeline using GitHub Actions and Google Cloud Build that builds, tests, and deploys the application.

**Cloud Build**
Google Cloud's CI/CD service used to build Docker images and deploy to Cloud Run.

**Cloud Run**
Google Cloud's serverless container platform where the backend is deployed.

**Cloud SQL**
Google Cloud's managed database service. Planned for PostgreSQL hosting in Phase 2.

**CORS (Cross-Origin Resource Sharing)**
A browser security mechanism. Currently misconfigured with `allow_origins=["*"]` — needs hardening.

**Competence**
A subject-matter domain or area of expertise (e.g., Electrical Systems, Mechanical Design). The platform has 7 competences.

**Competence Leader**
A user assigned as the leader of a competence, responsible for that domain's knowledge quality.

**Confidentiality Level**
A classification for knowledge assets indicating who can access them: L0 (Public), L1 (Internal), L2 (Confidential), L3 (Restricted), L4 (Top Secret — defined but unused).

**CRUD (Create, Read, Update, Delete)**
The four basic operations on data. User management CRUD is not yet implemented.

**CSRF (Cross-Site Request Forgery)**
An attack where a malicious site tricks a user's browser into making unwanted requests. No CSRF protection currently implemented.

---

## D

**dangerouslySetInnerHTML**
A React property that renders raw HTML content. Used in AssetDetail to display knowledge content. Requires HTML sanitization for security.

**Dashboard**
The main landing page showing KPIs, recent assets, pending approvals, and governance status.

**Docker**
Containerization platform used to package both the backend and frontend for consistent deployment.

**Draft**
The initial status of a knowledge asset before it is submitted for review.

---

## E

**Embedding**
A numerical representation of text used for semantic search. Generated by LLM providers (OpenAI, Anthropic). Not yet implemented.

**Employee**
The base user role. Employees can search, view, and submit knowledge assets.

**EOL (End of Life)**
The point at which a knowledge asset is no longer valid or relevant. Currently not tracked separately from Archived status.

---

## F

**FastAPI**
The Python web framework used for the backend API. Provides automatic OpenAPI documentation.

**FK (Foreign Key)**
A database constraint linking a column in one table to a column in another. Disabled in SQLite; enforced in PostgreSQL.

---

## G

**GCP (Google Cloud Platform)**
The cloud provider used for deployment (Cloud Run, Cloud Build, planned Cloud SQL).

**GDPR (General Data Protection Regulation)**
EU regulation governing data privacy. The platform has gaps in GDPR compliance (no export, no deletion, no consent management).

**Governance**
The system of policies, processes, and controls ensuring knowledge quality and compliance.

---

## H

**Hardcoded**
Values or logic written directly in the code rather than loaded from a database, configuration file, or API. Several KPI values and AI answers are hardcoded in the current implementation.

---

## I

**ISO 30401**
An international standard for Knowledge Management Systems. The platform is designed with ISO 30401 principles in mind but is not certified or fully compliant.

**IT (Information Technology)**
Often used to refer to the technical/IT competence or the technical aspects of the platform.

---

## J

**JWT (JSON Web Token)**
A token format used for authentication. Planned for implementation in Phase 2 to replace the current name-based login.

---

## K

**KPI (Key Performance Indicator)**
A measurable metric displayed on the Dashboard: total_assets, pending_reviews, overdue_docs, active_competences, published_this_month, active_users, approval_queue, avg_review_time.

**Knowledge Asset**
The core entity in the system — any piece of knowledge content with metadata (title, type, status, confidentiality, tags, etc.).

**Knowledge Lifecycle**
The progression of a knowledge asset through stages: Draft → Submitted → Champion Review → Leader Approval → Published → Review Due → Archived.

---

## L

**L0-L4 (Confidentiality Levels)**
- L0: Public — accessible to all users including Community Members
- L1: Internal — accessible to all authenticated users
- L2: Confidential — restricted to specific roles/competences
- L3: Restricted — highly sensitive, limited access
- L4: Top Secret — defined in types but not implemented

**L4**
The highest confidentiality level. Defined in the TypeScript types but never used in the backend or UI.

**Leader**
A user role with management-level permissions. Leaders approve knowledge assets during the Leader Approval stage and may manage competences.

**Leader Approval**
The final approval stage before a knowledge asset is published.

**LLM (Large Language Model)**
AI models like GPT-4 or Claude that generate text. Planned for integration in Phase 2 to power AI search answers.

**LlamaIndex**
A framework for building RAG applications. Planned for Phase 2.

**localStorage**
A browser storage API used to persist the user session in the frontend. Sessions persist indefinitely without expiry.

**Login**
The authentication step. Currently role/name selection; will become password-based with JWT in Phase 2.

---

## M

**Manual**
A type of knowledge asset — comprehensive documentation for equipment, systems, or processes.

**Middleware**
Software that sits between the request and the response. FastAPI middleware handles CORS; auth middleware planned for Phase 2.

**Mock Data**
Hardcoded or static data used to simulate real data. AI answers and training data are currently mocked.

---

## N

**N+1 Query Problem**
A performance issue where related data is fetched in a loop instead of a single query. Mitigated in this codebase using SQLAlchemy's `selectinload`.

**Notification**
Alerts sent to users when events occur (e.g., asset submitted for review, approval granted). Not yet implemented.

---

## O

**ORM (Object-Relational Mapping)**
A technique for accessing database data using object-oriented code. SQLAlchemy 2.0 is the ORM used in this project.

**OpenAPI**
A specification for API documentation. FastAPI generates OpenAPI docs automatically at `/docs`.

---

## P

**Pagination**
The practice of splitting large result sets into pages using `skip` and `limit` parameters.

**Password Hash**
A one-way cryptographic transformation of a password. Not implemented — Phase 2 priority.

**pgvector**
A PostgreSQL extension for storing and querying vector embeddings. Planned for Phase 2.

**PostgreSQL**
The production database system planned for Phase 2 (replacing SQLite).

**Procedure**
A type of knowledge asset — step-by-step instructions for performing a task.

**Production**
The live, user-facing environment. The current platform is not production-ready.

**Prototype**
A preliminary version of the system with core functionality but incomplete features. This is the current state.

**Pydantic**
A Python data validation library used by FastAPI for request/response schemas. Currently used minimally; full validation planned.

---

## Q

**Query Parameter**
URL parameters used to filter or paginate API responses (e.g., `?competence_id=1&limit=10`).

---

## R

**RAG (Retrieval-Augmented Generation)**
An AI technique that retrieves relevant documents and feeds them to an LLM to generate contextual answers. Planned for Phase 2.

**React**
The JavaScript library used for the frontend UI.

**Refresh Token**
A long-lived token used to obtain new access tokens without re-authentication. Planned for Phase 2.

**Role**
A user's permission level: Employee, Champion, Leader, Admin, Community Member.

**RSA (Root Cause Analysis)**
A type of knowledge asset documenting the investigation of a problem's underlying cause.

---

## S

**Search**
The ability to find knowledge assets by keywords, filters, or semantic similarity.

**Seed Data**
Initial data loaded into the database on first run: 7 users, 7 competences, 30 knowledge assets, 3 approval workflows.

**SEO (Search Engine Optimization)**
Not a focus of this application (it's an internal enterprise tool).

**Session**
A period of authenticated access. Currently persisted in localStorage without expiry.

**SlowAPI**
A rate-limiting library for FastAPI. Planned for Phase 2.

**Spiral Search**
The platform's 7-layer deep search feature: Documents → Lessons Learned → Cases → Cross-Competence → Experts → Training → Open Actions.

**SQL (Structured Query Language)**
The language for querying databases. SQLAlchemy generates SQL queries programmatically.

**SQLAlchemy**
The Python ORM used for database operations in the backend.

**SQLite**
The current database engine — a file-based database. Planned to be replaced by PostgreSQL.

**SSO (Single Sign-On)**
Authentication using an external identity provider (e.g., Azure AD, Google Workspace). Planned for Phase 4.

**Staging**
A pre-production environment for testing. Not currently set up.

---

## T

**Tags**
Keywords associated with knowledge assets for categorization and search. Currently stored as comma-separated text.

**Tailwind CSS**
The CSS framework used for styling the frontend.

**Test Coverage**
The percentage of code covered by automated tests. Currently 0%.

**Token**
In JWT authentication, a signed string representing a user's session. Planned for Phase 2.

**Training**
A type of content associated with competences. Currently hardcoded; planned for LMS integration.

**TypeScript**
The typed superset of JavaScript used for the frontend.

---

## U

**UI (User Interface)**
The visual layer of the application — the React frontend.

**URL (Uniform Resource Locator)**
Web addresses. The backend API base URL is `/api`.

**User**
A person with access to the platform. Seeded with 7 default users.

**User Role**
The permission level assigned to a user: Employee, Champion, Leader, Admin, Community Member.

---

## V

**Vite**
The build tool and dev server for the frontend.

**Vector Search**
Search based on the semantic similarity of text embeddings rather than keyword matching. Planned for Phase 2 with pgvector.

---

## W

**Workflow**
See "Approval Workflow."

**Workflow Stage**
A step in the approval process: Draft, Submitted, Champion Review, Leader Approval, Published, Review Due, Archived.

---

## Z

*No entries for X, Y, or Z in the NorthStar Knowledge OS glossary.*
